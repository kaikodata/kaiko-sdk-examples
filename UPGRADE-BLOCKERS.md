# Upgrade blockers

Version constraints that keep a dependency, tool or runtime below its latest release. Update this file
whenever one of them is lifted. State as of 2026-11-11; no Dependabot or grype finding is left open by
any row below.

Most rows have the same cause: each example must run against the published Kaiko SDK, whose generated
code comes from protoc 21.12, so the protobuf runtime of a language can only move as far as that
generated code allows. The SDK's own blockers are listed in kaikodata/kaiko-sdk `UPGRADE-BLOCKERS.md`.

| Bump | Blocked by | Unblock |
| -- | -- | -- |
| `google-protobuf` 3.21.4 → 4.0.3 (`node/package.json`) | the Node SDK is generated by protoc-gen-js 3.21.4, whose code targets `google-protobuf` 3.x | the SDK moves to protoc-gen-js 4.x; then bump here and run `npm run tsc` and an example |
| C++ protobuf 3.21.12 → 6.x and grpc 1.54.3 → 1.81.2 (`cpp/conanfile.txt`; grype High on grpc 1.54.3) | the SDK's C++ headers fail to compile against any other protobuf: they contain `#if PROTOBUF_VERSION < 3021000` and `#if 3021012 < PROTOBUF_MIN_PROTOC_VERSION` errors, and newer conan grpc packages require a newer protobuf | the SDK moves its protoc (see its `PROTOC-UPGRADE.md`); then bump both here together and run `client-cpp.yml` |
| cmake 3.28.1 (`cpp/conanfile.txt`) and gcc 11 (`cpp/Dockerfile.conan`) | they build grpc 1.54.3 and its abseil from source; that build has not been run with a newer compiler or CMake 4, which drops support for projects declaring a minimum below 3.5 | bump with the grpc move above |
| protobuf-java 3.25.9 → 4.x (`java/build.gradle`, `scala/project/Dependencies.scala`) | grpc-java 1.85.1 depends on protobuf-java 3.25.9, and the Java SDK's generated code comes from protoc 21.12 | the SDK moves its Java generation to protoc 4.x (see its `PROTOC-UPGRADE.md`) |
| Gradle 8.14.7 → 9.x (`java/gradle/wrapper`) | Gradle 9 needs Java 17 to run; `client-java.yml` builds with Java 11, the floor the examples document | raise the documented Java floor and `client-java.yml` to 17 or later, then run `./gradlew wrapper --gradle-version <latest>` |
| retry4j 0.15.0 (`java/build.gradle`, `scala/project/Dependencies.scala`) | latest release, but abandoned upstream (no release since 2018) | replace it in the resubscribe examples with a maintained library (for example failsafe) |
| scalapb-json4s 0.12.3 → 1.0.0 (`scala/project/Dependencies.scala`) | 1.0.0 is not released yet (alpha only) | bump when it is released |
| Python 3.11 in `client-python.yml` and `Pipfile`, 3.12 in `pyproject.toml` / `.python-version` | the two install paths (pipenv, uv) declare different floors; neither has been run on 3.14 | align both on the latest Python, then run `pipenv install` and `uv sync` with an example |
